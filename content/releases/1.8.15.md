## AS-IS

Everything from v1.0.0 to v1.8.14 is unchanged. No screen, field or behaviour was removed.

**The bucket fix from v1.8.13 worked.** The destination is now correct — `s3://cvs-whd-v1-20261014/CVS/app/android/1.0.0.12/…` — and a signed `.apk` reached it. Only the credentials were missing.

## Fixes

- **`NoCredentialsError: Unable to locate credentials`.** The upload runs **on the GitHub runner**, so it uses `AWS_ACCESS_KEY_ID` and `AWS_SECRET_ACCESS_KEY` from the **repository's** secrets. They are not set there. The platform's own AWS credentials are a different thing and cannot be reached from a GitHub runner.

- **This is now the first thing the build checks, not the last.** A new first step confirms the repository has `MOBILE_BUILD_SECRET`, `AWS_ACCESS_KEY_ID` and `AWS_SECRET_ACCESS_KEY`, and stops in about a second if any is missing — naming them, and saying where they go. Until now the build installed 1,181 packages, bundled the JavaScript and compiled the app for six minutes before finding out it had nowhere to put the result.

- **"Set up secrets in GitHub" now writes the AWS credentials too.** It already wrote `MOBILE_BUILD_SECRET` and `BUILD_TRIGGER_SECRET`; it now also sends `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY` and `AWS_REGION` when the platform has them. Each is sealed to the repository's own public key before it leaves, as the others are.

  The panel says plainly which five it sends, because credentials moving from one place to another should never be a surprise. If you would rather add them by hand, nothing has changed — the button is a convenience, not the only route.

## What to do

Either press **Set up secrets in GitHub** on *Mobile App Release*, or add these two in GitHub → Settings → Secrets and variables → Actions:

| Secret | Value |
| --- | --- |
| `AWS_ACCESS_KEY_ID` | the same key the platform uses |
| `AWS_SECRET_ACCESS_KEY` | its secret |

The key needs `s3:PutObject` on `cvs-whd-v1-20261014`. Then build again.

## A note on where the time went

The last four failures were all the same shape: something the build needed existed on the platform but not in the repository — the workflow file, the app source, the bucket, and now the credentials. Each one was found by running the build and waiting.

The first step added here closes that off for the repository's secrets, and *Check GitHub setup* already covers the other three. A build should fail in the first second or not at all.
