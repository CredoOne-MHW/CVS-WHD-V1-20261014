## AS-IS

Everything from v1.0.0 to v1.8.5 is unchanged. No screen, field or behaviour was removed.

## Fixes

- **`ENOENT: no such file or directory, open './assets/icon.png'` — Prebuild failed.** `mobile/assets/` was an empty folder. It has been empty since v1.5.0: `app.json` named four images, the folder was created, and the images themselves were never put in it. Expo's prebuild reads the icon to make every Android density, so it died before the app was compiled — with an ENOENT stack trace from inside `@expo/image-utils` that says nothing about what to do.

  **Four images are now committed in `mobile/assets/`:**

  | File | Size | What it is |
  | --- | --- | --- |
  | `icon.png` | 1024² | The full-bleed icon, for iOS and both store listings |
  | `adaptive-icon.png` | 1024² | The Android adaptive foreground, with the mark inside the safe area so a circular or squircle mask does not cut it |
  | `splash.png` | 1242² | Shown over the splash colour, which is set to the company's own |
  | `notification-icon.png` | 96² | The small monochrome mark Android draws in the status bar |

  The mark is a hive cell in the platform's green and honey — deliberate rather than placeholder, and tied to no particular industry.

- **A company's own icon still wins.** When one has been uploaded, the build downloads it and it replaces both icon shapes, as before. The log now says which of the two happened, instead of being silent when it used the default.

- **A missing image now fails with a sentence, not a stack trace.** `brand.mjs` checks all four exist before prebuild runs and names any that do not, with where they should be.

## Updates / Modifications

- **`app.json` now points the Android adaptive icon and the notification icon at their own images**, rather than reusing the full-bleed one for all three. Android masks the adaptive foreground, so a full-bleed image loses its edges; and the status-bar mark has to be a flat silhouette or Android draws a grey square.

## What to do

**Push the `mobile/` folder** — the new part is `mobile/assets/` and the updated `app.json` and `scripts/brand.mjs`. Then build again.

**To give a company its own icon:** upload one under that company's Branding, and the next build uses it. Upload it already padded if you care how it looks under Android's circular mask, since the same image is used for both shapes.
