## AS-IS

Everything from v1.0.0 to v1.8.4 is unchanged. No screen, field or behaviour was removed. This release fixes the first real build failure on GitHub — the workflow now dispatches and runs, which it never did before v1.8.4.

## Fixes

- **`Error: Some specified paths were not resolved, unable to cache dependencies.`** The workflow asked `actions/setup-node` to cache npm packages keyed on `mobile/package-lock.json`, and that file had never been committed. `setup-node` does not treat a missing cache path as "skip the cache" — it fails the step outright, which failed the build before a single line of the app was compiled.

  Two things were wrong, and both are fixed:

  1. **`mobile/package-lock.json` is now in the repository.** All 17 dependencies resolved, 1,188 packages, `lockfileVersion 3`. This is worth having for its own sake: `npm ci` installs exactly these versions every time, so two builds of the same company's app a month apart produce the same thing. Without it, `npm install` was free to pick up a newer patch release of any dependency mid-build.
  2. **Caching is now switched on only when the lockfile is there** — `cache: ${{ hashFiles(...) != '' && 'npm' || '' }}`. A missing lockfile now means "no cache", not "no build".

- **The Install step says which way it went.** With a lockfile it runs `npm ci` (falling back to `npm install` if the lockfile and `package.json` have drifted apart); without one it runs `npm install` and leaves a warning in the log saying the build may not match the last one.

## What to do

**Push the updated `mobile/` folder**, including the new `mobile/package-lock.json`, along with `.github/workflows/build-mobile.yml`. Then start the build again.

## A note on where this sits

The workflow reaching `setup-node` at all means the platform side is now correct end to end: the build dispatched, GitHub accepted it, the runner started and checked the code out. What remains are the ordinary problems of building a React Native app in CI, which fail loudly in the run log with the compiler's own words.
