## AS-IS

Versions 1.0.0, 1.1.0 and 1.2.0 continue unchanged except where listed below. No module, screen, field, permission or fix from an earlier version has been removed — Sales Order grouping, Convert to Invoice, the Outstanding / Upcoming split, Company Name on leads, WhatsApp Logs, Integration › Needs attention, the compact interface, the Client Journey scroll area and the OTP-verified client delete all behave exactly as before. Creating a company still uses the same pop-up.

## New Features

- **A company now opens as its own page.** Clicking a company’s name (or the pencil) in Super Admin › Company opens a full workspace at `/sa/companies/<id>` with a header — logo, status, plan, code, login e-mail, created date and address — and the actions that apply to the whole company: **Force login**, **Login page**, **Suspend / Activate** and **Save changes**. A new company is created in the same pop-up as before and then opens on its own page.
- **Overview** — this platform’s own figures for the company: leads in 7 days and in all, conversions, clients, outstanding (with upcoming shown separately), users and AI credits, live connectors, deliveries needing attention, open tickets, its three addresses with copy buttons, its users with last sign-in, its latest leads, and the current subscription cycle.
- **Company details** — legal name, business type, GSTIN, address, city, state, PIN, contact person, phone, WhatsApp, company e-mail, a separate contact e-mail and account status, beside the name, short name and code.
- **Subscription** — plan, payment frequency, amount, first due date, discount as ₹ **or** %, and the gross it works out to, with the current cycle shown underneath.
- **Login credentials** — owner name, WhatsApp, login e-mail and a new password with **Show** and **Generate**.
- **Branding & domain** — platform address and own domain, the company’s images, theme and accent colours, the 10 login designs with a live preview, the login page text, **login page colours** (headline, sub-headline, company name, tagline, “Sign in” title, form text, button and button text — each one Auto or a colour of its own) and **app themes** for the web and mobile apps. The S3 panel now lists what each area of the company’s folder holds.
- **White label** — hide platform branding, support link, e-mail sender name, app names for the web, mobile and admin apps, sidebar, corners and font, and custom CSS.
- **Role access** — the company’s own roles, edited by Super Admin, on the same grid the company sees. Everything is capped by the plan and by the Modules tab, so a paused module can never be granted. Saving a role here marks it as set by Super Admin.
- **Mobile Modules** — tick which modules and sub-modules this company’s mobile apps may use. The list is the platform’s own menu, so modules added later appear by themselves and start ticked.
- **Notifications** — every in-app notification with its own Mobile and Desktop switches and a sound, “apply one sound to all”, and **custom sounds** uploaded to the company’s own S3 folder.
- **Cron Jobs** — every background job with its schedule, last run and duration, next run, an on/off switch and **Run now**. A company can set its own interval or daily time for the jobs that work company by company; jobs that run once for the whole platform are marked **platform-wide** and can still be run for this company on demand.
- **Retention Policy** — how long each kind of log is kept, with its record count and oldest record, a per-row **Apply** and an **Apply now** for all. A new nightly housekeeping job (01:00 IST) deletes what is past its period. Logs that an audit may need have a floor and cannot be shortened below it.
- **Per-company S3 layout** — everything a company owns now sits under its own prefix: `branding/` (logo, banner, favicon, sounds), `app/` (mobile builds pushed by GitHub Actions), `brain/` (AI knowledge), `dpdp/` (consent documents) and `<Client Code>/<type>/` (attachments).

## Updates / Modifications

- **Editing a company moved out of the pop-up** onto the new page. The pop-up is still what creates a company, with the same four tabs; nothing was removed from it.
- `retry`, `billing` and `followups` now do their work company by company, each on that company’s own schedule, and record every run. The other jobs behave exactly as before and simply record their runs so the tab can show them.
- **Role Management inside the company** is unchanged. A role Super Admin saves is marked as set by Super Admin, which the company’s own screen shows.

## Fixes

- **A menu click that did not land.** After a deployment, a tab still running the old build cannot load the new code chunks; the route change was cancelled silently, the screen stayed where it was, and clicking another menu item did nothing until the page was reloaded by hand (the automatic stale-build reload is throttled to once in 30 seconds, which left the second and third click stranded). Every menu click is now watched: if the address has not changed a moment later, the browser is sent there directly, which fetches the new build and lands on the page that was clicked. The event is recorded in Activity Logs as a screen error, so a recurrence is visible.
