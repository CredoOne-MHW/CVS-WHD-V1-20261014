## AS-IS

v1.3.0 and everything before it is unchanged. The company workspace, its twelve tabs, the per-company S3 layout and the stuck-menu fix all behave exactly as they were delivered.

## Fixes

- **The shared cache was silently off.** The platform only looked for `UPSTASH_REDIS_REST_URL` and `UPSTASH_REDIS_REST_TOKEN`. A Redis store added from the Vercel marketplace is given different names — `KV_REST_API_URL` for Vercel KV, or a store-prefixed pair such as `REDIS_UPSTASH_LIGHTHOUSE_KV_REST_API_URL` — so the platform found nothing and every serverless instance kept its own copy of the cache. A change could then take a few seconds to show on another instance, and the same query was run once per instance. The pair is now found by itself: the hand-set names first, then Vercel KV's, then any `<STORE>_KV_REST_API_URL` with its matching token. A read-only token is ignored, because the cache has to write. Nothing needs renaming in Vercel.

## New Features

- **Super Admin › Settings › System Health shows the cache.** A card says whether it is On, how long a round trip takes and which variable it came from, and a banner appears when no store is configured at all — so this can never be wrong quietly again.

## Updates / Modifications

- `.env.example` now lists every variable the code reads, including all three accepted Redis pairs and the mobile-app build settings that v1.5.0 will use (`GITHUB_BUILD_REPO`, `GITHUB_BUILD_TOKEN`, `GITHUB_BUILD_REF`, `GITHUB_BUILD_WORKFLOW`, `MOBILE_BASE_VERSION`, `MOBILE_PACKAGE_PREFIX`, `MOBILE_IOS_SIGNING`). The Android and iOS signing keys are listed where they belong — in the build repository's GitHub secrets, never in the platform's environment.
