## AS-IS

Everything from v1.0.0 to v1.8.12 is unchanged. No screen, field or behaviour was removed.

**The app itself built.** A signed 66 MB `.apk` came out of that run — install, branding, prebuild, signing, JS bundling and all 34 Gradle tasks succeeded. Only the upload failed, and only because it had no bucket to upload to.

## Fixes

- **`upload failed: … to s3:///CVS/app/… Invalid bucket name ""`.** Three slashes: an empty bucket name. The upload runs **on the GitHub runner**, not on the platform, and the workflow read an `S3_BUCKET` **repository secret** — a second place to configure the same thing, which nobody had filled in because the platform's own `S3_BUCKET` was set and showing a green tick.

  **The platform now sends its bucket with every build**, inside the destination it already passes. There is no second place to configure, so the two can no longer disagree.

  A repository that still has an `S3_BUCKET` secret keeps working: the workflow uses the address the platform sends when it is a full `s3://` one, and falls back to the secret otherwise. And if there is no bucket either way, it now says so in one line — *"The app built fine — only the upload had nowhere to go."* — instead of printing an AWS regex.

- **"Check GitHub setup" now checks the repository's own secrets.** The runner reports back and uploads, so it needs `MOBILE_BUILD_SECRET`, `AWS_ACCESS_KEY_ID` and `AWS_SECRET_ACCESS_KEY` of its own. The checklist listed the AWS pair as platform settings only, which is where the confusion came from. It now lists them for the repository too, and the live check names any that are absent.

## Verified

The address parsing is the whole fix, so it was run against every case rather than reasoned about: a full `s3://bucket/path` from the current platform, a deep path, a bare prefix with the old repository secret, no bucket anywhere (refused with the plain message), and a bucket with no path at all. That last one found a real bug before it shipped — `${REST#*/}` leaves the string untouched when there is no slash, which would have put the bucket name inside the key.

`npm test` — 53 checks, all passing.

## What to do

Push `.github/` and deploy the platform. Nothing to configure: the bucket comes from the platform's own `S3_BUCKET`, which is already set.

While you are in GitHub, check the repository has **`AWS_ACCESS_KEY_ID`** and **`AWS_SECRET_ACCESS_KEY`** as secrets — the upload needs them, and *Check GitHub setup* will now tell you if they are missing.
