## AS-IS

Everything from v1.0.0 to v1.10.0 is unchanged. **No screen, field, module or behaviour has been removed, renamed or moved.** Every existing conversation, group, notice, attachment, permission and build works exactly as before.

Specifically preserved in the app's Chats:

- **Every message already sent** renders as it always did; nothing was migrated.
- **Attachments** — sending, opening, Save, the 20 MB limit and the "Exceeded File Size" wording — unchanged.
- **New chat**, **New group** and the people picker — unchanged, same permissions.
- **The scrolling notice** at the top of the app — unchanged.
- **The web Chats page is untouched.** This release changes the phone only.
- **Polling fallback** still works when there is no real-time service; everything new degrades to it rather than depending on it.

## New Features

### The conversation now looks and behaves like a phone messenger

These are the conventions every messaging app has settled on, and they are now all here:

- **Bubbles with a tail**, drawn from borders so they take the bubble's own colour and stay sharp at any screen density.
- **The time inside the bubble**, tucked into the bottom-right corner rather than on its own line.
- **Ticks on your own messages** — ✓ when sent, **✓✓ in blue** once everyone in the conversation has read it, and a clock face while it is still going out.
- **Date separators** — *Today*, *Yesterday*, *Monday*, then a full date.
- **Consecutive messages grouped**. Three messages from one person in a minute form one block with one timestamp and one tail, instead of three identical-looking bubbles.
- **Sender names in colour** in groups, and the same person is always the same colour everywhere — the colour comes from their id, not their position in the list, which is the whole point of colouring them.
- **A jump-to-latest button** that appears only when you have scrolled away from the newest message.
- **"… is typing"**, sent at most once every three seconds (one request per keystroke would be absurd) and clearing itself four seconds after the last signal.
- **A rounded composer** with the attach button inside the field and a round Send button beside it.
- **The conversation sits on a tinted ground**, so bubbles read as cards on a surface.

**On colour:** the palette is **each company's own brand colour**, taken from the build — not anybody else's. This app is white-label, so a borrowed palette would be wrong for every company that is not that brand, and no other company's logo, artwork or assets are used anywhere in this.

### Messages appear the instant you send them

Your message now appears in the conversation immediately, carrying a clock face where its ticks will be, and is replaced by the real one when the server answers. On a weak signal that is the difference between an app that feels instant and one that appears to have swallowed what you typed. **If the send fails the placeholder is removed and your text goes back into the box**, so nothing is lost either way — the same guarantee as before, now visible.

### The conversation list reads at a glance

- **A tick on your own last message**, so you can see what has been read without opening anything.
- **"You:" or the sender's first name** in front of a group's last message.
- **Phone-style times** — a clock time today, *Yesterday*, then a short date.
- **An unread count** in the company's brand colour, with the time and preview emphasised while unread.
- **A search box** that filters what is already loaded — no request per keystroke.

## Update / Modifications

### Fixed: ticks could never have changed

Worth stating plainly, because it would have shipped as a feature that quietly never worked.

The app catches up by asking only for messages **newer** than the last one it holds. A read receipt arrives against a message that is already on screen, so under that scheme it could never arrive at all — a sent message would have shown one tick for the rest of its life.

Two things now carry it: the conversation subscribes to the **`message.read`** signal, which moves the ticks live; and where there is no real-time service, every sixth poll (about half a minute) the visible page is re-read and **only the read counts are merged in**, leaving scroll position untouched and moving no message. That second path is why this works on a weak connection rather than only on a good one.

### A small server change behind the list ticks

`lastMessage` on a conversation now also records **who sent it** (`byId`). Without that the list could only compare display names to guess whether the last message was yours, which breaks the moment two people share a first name. It is one additional field; nothing was changed or removed, and existing conversations simply gain it on their next message.

### Scroll no longer jumps while you are reading back

Arriving messages used to scroll the conversation to the bottom unconditionally. If you were reading something from last week, it yanked you away. **It now only follows the conversation when you are already at the newest message** — otherwise the jump button appears and the choice is yours.

## Performance

- Typing is announced at most once every three seconds, not once per keystroke.
- Search filters what is already loaded; it makes no requests.
- Read counts refresh over the real-time channel when it is available, costing nothing; the polling fallback adds **one request per half-minute** and only while a conversation is open.
- Grouping and date pills are computed in one pass over the messages already held.
- Ticks and date pills are memoised, so a new message does not re-render every bubble above it.

## Logs

Unchanged. Messages, attachments and read receipts are recorded exactly as before; none of the above adds or removes a record.

## Verified

- `npx tsc --noEmit` clean on both the platform and the app.
- `npm test` — **125 checks**, including **32 new ones** covering message grouping, tick states, date pills and list times.
- `npm run build` clean.
- `npm run verify:bundle` — Metro bundles the app exactly as Gradle will.

**One thing this check earned its keep on:** the layout rules were first put in `shared/`, alongside the platform's other shared code. The bundle check refused it — the build repository receives only `mobile/` and `.github/`, so `shared/` is not there and the app would have failed to build after a twenty-minute wait. It now lives in `mobile/src/lib/`. This is the same class of failure as the v1.8.12 `netinfo` one, caught before a build rather than after.

**What could not be verified here:** this container has no Android or iOS emulator, so the preview sent with this release is a hand-built layout preview, not a device screenshot. The real rendering comes from the build.
