## AS-IS

Everything from v1.0.0 to v1.14.0 is unchanged. **No screen, field, module or behaviour has been removed, renamed or moved.** Every screen that appeared in the menu before appears in it now, under the same permissions and the same Mobile Modules settings. Nothing about who may see what has changed in this release.

## Update / Modifications

### Fixed: the drawer took most of the screen and read as a web page's menu

What was there was React Navigation's **stock** drawer — the library's own default, never styled. Three things made it look like a menu on a page rather than part of an app, and the colours were not among them.

**1 · It was too wide, and worse the smaller the phone.** The library sizes a drawer to `screen − 56`, capped at 280. Because it subtracts a *fixed* amount, the narrower the phone the bigger the share it takes:

| Screen | Was | Now | |
|---|---|---|---|
| 320 dp — small phone | 264 (82%) | **224 (70%)** | 40 dp narrower |
| 360 dp — common Android | 280 (78%) | **252 (70%)** | 28 dp narrower |
| 393 dp | 280 (71%) | **275 (70%)** | 5 dp narrower |
| 412 dp — large phone | 280 (68%) | **280 (68%)** | same |
| 768 dp — tablet | 320 | **280** | 40 dp narrower |

The rule is now **70% of the screen, never past 280 dp**, so at least 30% of the app is always visible behind it and it is never wider than the value it replaced.

Worth recording why it is a proportion and not a subtraction: the obvious `screen − 64` is **wider** than the old default on a large phone. It was written that way first, and the comparison above is what caught it.

**2 · There was no sense of place.** Nothing said whose workspace this was or who was signed in. The drawer now opens with a brand header carrying the company, your name and your role.

**3 · Plain text links, no icons, no grouping.** Four words in a tall white rectangle. Rows are now compact with icons, the account section is separated from the menu, and the footer carries sign out and the build number — so when you ask someone which version they are on, it is in front of them.

### Fixed: the selected row was tinted green on a blue app

A real inconsistency, found while doing the above rather than reported.

`T.brand` is each company's own colour, set by its build. The *tint* behind a selected row was the literal value `rgba(47,92,36,…)` — the default green — so a company built in blue got a green-tinted selection sitting directly under its own blue header. The drawer now derives that tint from whatever the brand colour actually is.

### Changed: one label

The Dashboard row in the menu read **"CredoOne"**, because the screen's title doubles as its menu label. The top bar still says CredoOne — that is the branding — but the menu row now says **"Dashboard"**, which is what it is.

This is the only text in the product that changed. If you would rather it kept the company name there, say so and it goes back in a minute.

## Needs your decision — the same green is hardcoded in five more places

I fixed it in the drawer because the drawer is what this release is about. I have **not** touched the others, because they are in screens you did not ask me to change and I am not going to alter how Chats and Users look without you seeing it first.

| Where | What is tinted with the default green |
|---|---|
| `theme.ts` — `T.tint` | the shared tint token itself |

For a company built in any colour but the default, each of these is green next to its own branding. Fixing all five is a small, contained change — the helper is already written and tested. **Say "Allow" and it goes into the next release**; the impact is limited to the colour of those five elements, with no change to layout, behaviour or permissions.

## Verified

- `npm run preflight` — all five stages; **225 checks**, including **19 new ones**.
- The regression checklist gains a new section, **The app's own interface**, with entries **35**, **36** and **37**, all guarded by `test:drawer`.

Replacing a library's component buys the look and takes on the library's responsibilities, so the new checks are about the ways a custom drawer fails *silently*:

1. **Items are read from the navigator, never listed by hand.** The standing trap: a screen is added, nobody edits the drawer, and it becomes unreachable while the code declaring it looks correct. A screen with no icon mapped still gets one.
2. **Every icon name is checked against the font file.** A name that is not in the font renders as a blank box — nothing fails and nothing logs.
3. **The width is asserted to be narrower**, across six device widths, than the default it replaced.
4. **The hook's position is asserted.** A hook added below an early return crashes on the move from loading to signed-in and never on first paint, so it survives a glance.
5. **`@expo/vector-icons` is now declared in `mobile/package.json`** with the lockfile in step, rather than relied on because Expo happens to pull it in — which is exactly how the netinfo failure (row 10) happened.

All four of these were confirmed to actually fail when the thing they guard is broken, rather than assumed to.

**What cannot be verified here:** no phone in this container, so this is a faithful redraw from the stylesheet and a bundle that builds — not a photograph of a device. The numbers are the numbers in the code.
