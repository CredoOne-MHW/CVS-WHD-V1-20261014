## AS-IS

Everything from v1.0.0 to v1.8.15 is unchanged. No screen, field or behaviour was removed.

**Builds now work end to end.** A signed `.apk` is compiled, uploaded to the company's S3 folder, and the row reaches **Ready**.

## Fixes

- **`404 · Company not found` on Super Admin → Company → Mobile App.** This is the original bug, properly found at last. The tab was reported in v1.7.0 as a spinner that never stopped; that release made the failure visible and added a retry, but treated the symptom. The cause was underneath it all along.

  These routes are mounted at `/companies/:id`, and **an Express sub-router does not inherit its mount path's parameters unless it is created with `{ mergeParams: true }`**. It was not. So `req.params.id` was `undefined`, the company lookup matched nothing, and every request to the tab answered *"Company not found"* — first as an endless spinner, then as a 404 that made no sense next to a company page that had clearly loaded.

  **It has never worked**, since the tab was added in v1.5.0.

- **The DPDP tab had exactly the same bug.** It is mounted the same way and reads the same parameter. It had a fallback to `?companyId=`, which no screen passes, so it was equally broken — just not yet opened. Both routers now merge their parameters, and the dead fallback is gone rather than left to hide the next one.

## Verified

Three ways, because a fix for a bug that survived two releases deserves more than a glance:

- **The Express behaviour itself**, run rather than recalled: a plain sub-router reports `req.params.id` as `null`; with `mergeParams` it reports the real id.
- **Every router in the project mounted under a path parameter is now checked**, so a new one cannot repeat this.
- **The test was confirmed to fail** when the bug is put back, and pass when it is removed. A check that cannot fail is worth nothing.

`npm test` — 58 checks, all passing.
