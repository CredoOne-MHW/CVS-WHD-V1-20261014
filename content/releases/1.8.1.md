## AS-IS

Everything from v1.0.0 to v1.8.0 is unchanged. No screen, field or behaviour was removed. This release stops asking you for a setting the platform can make itself, and closes a hole in how that setting behaved when it was missing.

## Fixes

- **A missing `MOBILE_BUILD_SECRET` used to fail open.** The platform signed with the literal string `"dev"` (`env("MOBILE_BUILD_SECRET") || "dev"`) — a value printed in the source — so an unconfigured platform accepted any build result signed with that known string. `/api/public/mobile/build` decides which file a company installs as its app, and since v1.7.0 the same secret guards the endpoint that hands over a company's Android keystore. **With no secret, both now refuse.** The platform makes one on its own, so there is no longer any reason for it to be missing.

## Updates / Modifications

- **`MOBILE_BUILD_SECRET` is no longer an environment variable you have to invent.** The platform makes one the first time it is needed, keeps it, and shows it on the set-up panel to copy — exactly as `BUILD_TRIGGER_SECRET` has always worked. **An environment variable still wins where one is set**, so a platform already configured behaves exactly as before and the panel says which of the two is in use.
- **"Set up secrets in GitHub"** writes both shared secrets into the build repository over the GitHub API, so there is nothing to paste. GitHub will not accept a secret in the clear, so each value is sealed to the repository's own public key (libsodium sealed box) before it is sent.
  - It needs the build token to carry **Secrets: read and write** as well as Actions. Where it does not, the refusal is reported for each secret on its own and the values are still shown to copy — **the manual route never stops working**.
  - Each secret's outcome is reported separately, because "two of three worked" is the thing worth knowing.
- **A new callback secret can be made from the panel.** Everything building at that moment will fail to report back, which the screen says before it is pressed. A secret that came from the environment cannot be replaced from here — it says where to change it instead.
- **The set-up checklist understands what the platform keeps.** A row the platform holds is a tick with its own line — *"Kept by the platform — nothing to set here"* — not a red cross for a variable that is deliberately absent.
- **`setupState()` and `readyToBuild()` take an optional map** of what the platform holds. Called with nothing, both behave exactly as they did in v1.7.1.
- **`callbackValid()` is now async**, because it reads a stored secret. Both callers await it.

## What this means for you

If you have already set `MOBILE_BUILD_SECRET` in the environment: **nothing changes.** It still wins, and the panel says so.

If you have not: stop. Open **Super Admin → Mobile App Release → Set up in GitHub**, and either press **Set up secrets in GitHub**, or press **Show** and copy both values into the repository's secrets by hand. Nothing goes in the environment.

**One behaviour genuinely changes at deploy:** a platform that today has no secret set is silently signing with `"dev"`. After this it refuses until a secret exists — which is the point — so any build in flight at deploy time will fail to report back and need starting again.
