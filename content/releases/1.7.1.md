## AS-IS

Everything from v1.0.0 to v1.7.0 is unchanged. No screen, field or behaviour was removed. This release only makes the build set-up panel tell the truth about three settings it used to pass silently.

## Updates / Modifications

- **A setting that is present but unusable is no longer a green tick.** The checker only ever asked "is there a value?", so a wrong one passed and the build then failed on GitHub with a 404 and nothing useful to show for it. Three are now checked properly, and a bad one shows in amber with the correction rather than the complaint:
  - **`GITHUB_BUILD_REPO`** must be `owner/repo`. A full `https://github.com/owner/repo.git` is pasted straight into a GitHub address and cannot work — and when that is what it finds, the message names the short form to use.
  - **`GITHUB_BUILD_WORKFLOW`** must end in `.yml`. Another project's desktop workflow will not build an app.
  - **`MOBILE_BUILD_SECRET`** must be long enough to be a secret, with the command to make one.
- **A malformed setting also blocks the build**, the same as a missing one. Starting a build that is going to fail a minute later on GitHub helps nobody.
- **`MOBILE_SIGNING_SECRET` is now on the checklist, and clearly marked optional.** It was added in v1.7.0 and documented everywhere except the one screen whose job is to show what is missing. It is also worded properly now: leaving it empty and keeping the `ANDROID_*` secrets in the repository is **a complete set-up on its own**, not a lesser one.
- **`MOBILE_BUILD_SECRET`'s description now says what happens if the two values differ** — builds run but never turn Ready — because that is the symptom people actually meet.

## Fixes

- **`.github/workflows/build-mobile.yml` was not valid YAML.** The signing step contained a Python heredoc whose lines de-indented below the block they sat in, which ends the block early. GitHub would have rejected the whole file with *"Invalid workflow file"* on the first run. The Python now lives in `.github/scripts/android-signing-config.py` and the workflow calls it, which also means that script can be read and tested on its own. **This has been broken since v1.5.0** and nothing that depends on it has ever run.
