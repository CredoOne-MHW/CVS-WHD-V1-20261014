## AS-IS

Everything from v1.0.0 to v1.11.0 is unchanged. **No screen, field, module or behaviour has been removed, renamed or moved.** This release changes two build scripts and one workflow step. Nothing in the platform, the web app or the phone app's own code is touched.

## Update / Modifications

### Fixed: `Could not get unknown property 'MYAPP_UPLOAD_STORE_FILE'`

**This was introduced by v1.10.0 and it was my mistake.** Android builds would have failed at the Gradle step, about seventy seconds in, from v1.10.0 onward.

**What actually happened.** The workflow wrote the four signing values into `android/gradle.properties` by appending them with the shell:

```
{ echo "MYAPP_UPLOAD_STORE_FILE=release.jks"; … } >> android/gradle.properties
```

That is correct only while the file already ends in a newline. `expo prebuild` writes that file, and what it ends with depends on which config plugins are installed. **v1.10.0 added `expo-build-properties`** — to set the Android API level for Play — and with it installed the last line became `android.extraMavenRepos=[]` **with no trailing newline**. So the append produced:

```
android.extraMavenRepos=[]MYAPP_UPLOAD_STORE_FILE=release.jks
MYAPP_UPLOAD_KEY_ALIAS=cvskey
MYAPP_UPLOAD_STORE_PASSWORD=…
MYAPP_UPLOAD_KEY_PASSWORD=…
```

Gradle saw `android.extraMavenRepos` with a strange value and **no `MYAPP_UPLOAD_STORE_FILE` at all**. The other three were on their own lines and were perfectly fine — which is exactly why the error named only the first one, and why it read as a mystery rather than as a missing file.

**How it was found.** Rather than guessing, `expo prebuild` was run here against the real project, with and without `expo-build-properties`:

- without it, the file ends `android.useLegacyPackaging=false` **with** a newline — which is why every build up to v1.9.x worked;
- with it, the file ends `android.extraMavenRepos=[]` **without** one.

The old append was then run against that real file and reproduced the failure exactly: `MYAPP_UPLOAD_STORE_FILE` came back undefined while `MYAPP_UPLOAD_KEY_ALIAS` came back correct — the precise shape of the error you saw.

**The fix.** The properties are no longer appended. A new script reads the file, replaces those four keys, writes it back, and then **reads it again to check Gradle will really find all four**, failing in a second with a plain message if not — rather than twenty minutes later inside Gradle. It also means running it twice replaces rather than duplicates a key, handles a value containing `=` (a password often does), and strips Windows line endings that would otherwise leave a carriage return inside a password.

### The Gradle file now explains itself if this ever recurs

The generated signing block used a bare `MYAPP_UPLOAD_STORE_FILE`. When that is not defined, Groovy's error is *"Could not get unknown property … for SigningConfig$AgpDecorated_Decorated{…}"*, which tells nobody what to do.

It now reads the property defensively and, if it is missing, stops with a sentence saying which property it is, which workflow step is supposed to write it, and what it means if that step did not run.

## Performance

Unchanged. The new script is one file read and one write, replacing an append.

## Logs

Unchanged. The signing values are never printed — the script reports only the names of the keys it set, never their values.

## Verified

- `npm test` — **146 checks**, including **21 new ones** for this. The first of them is this exact failure, reproduced: a properties file ending `android.extraMavenRepos=[]` with no newline, which now resolves correctly and would have failed before.
- The whole sequence was run here against a **real `expo prebuild` output** — prebuild, write the properties, patch `build.gradle` — and all four properties come back correctly, with `android.extraMavenRepos` left intact on its own line.
- `npx tsc --noEmit` clean on both the platform and the app; `npm run build` clean; `npm run verify:bundle` bundles.

**Still not verifiable here:** this container has no Android SDK, so Gradle itself cannot be run. What has been proved is that the properties Gradle reads are now present and correct, which is the thing that was broken.

## Build repository

`mobile/` and `.github/` **must be pushed before the next Android build** — the fix is in `.github/scripts/`, so the platform alone does nothing. The revision markers were bumped to `1.11.1`; Mobile App Release will report the repository as behind until it is pushed.
