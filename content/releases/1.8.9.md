## AS-IS

Everything from v1.0.0 to v1.8.8 is unchanged. No screen, field or behaviour was removed.

## Fixes

- **`Could not make the signing key: spawn keytool ENOENT`.** The platform-held signing key, added in v1.7.0, was made by shelling out to **`keytool`** — a program that belongs to the JDK. The platform runs on a Node runtime, which has no JDK and never will. So the very first Android build of every company failed, and no setting could have fixed it. That was a design error on my part, not a configuration problem: I reached for the tool I would have used at a terminal without asking whether the server had it.

  **The keystore is now built in JavaScript**, with `node-forge`: an RSA-2048 key, a self-signed certificate valid for 10,000 days, and a PKCS#12 keystore — the same artefact `keytool -storetype PKCS12` produced, and exactly what Gradle reads.

- **One password, not two.** The old code made separate store and key passwords. PKCS#12 keeps one, and Java refuses a keystore where they differ — so that first build would have failed again even with a JDK present.

- **The fingerprint is now the certificate's.** It is the SHA-256 of the certificate, which is what Play Console shows and what an installed phone compares. The old code fell back to hashing the keystore file, a number that matches nothing.

- **Making a key no longer blocks the server.** RSA generation ran synchronously and held the event loop for several seconds, so one company's first build made every other request wait. It now yields between rounds.

## Verified

Against a real JDK, once, which is the only way to be sure:

- **`keytool -list -v`** reads the keystore and reports `Entry type: PrivateKeyEntry`, the right alias, `SHA256withRSA`, validity to 2054, and **the same SHA-256 fingerprint** the platform recorded.
- **`jarsigner`** signs with it, and `jarsigner -verify` answers **"jar verified"**. (It warns the certificate is self-signed, which is correct — every Android app signing certificate is.)

And on every run, with no JDK needed: `npm test` now includes eleven checks that the keystore opens with its password and not another, holds exactly one usable private key under the company's alias, carries a self-signed certificate lasting well past 25 years, produces a real SHA-256 fingerprint, and gives every company a different key.

## What to do

Deploy and build again. `MOBILE_SIGNING_SECRET` is already set, and nothing else is needed — the first Android build of each company now makes that company's permanent key and signs with it.

**The failed builds in the table can be left alone.** No key was stored, so nothing is half-made; the next build starts clean.
