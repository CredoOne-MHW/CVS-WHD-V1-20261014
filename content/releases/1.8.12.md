## AS-IS

Everything from v1.0.0 to v1.8.11 is unchanged. No screen, field or behaviour was removed.

## Fixes

- **`Unable to resolve module @react-native-community/netinfo` — `createBundleReleaseJsAndAssets` FAILED.** Chat connects through `pusher-js/react-native`, and that build of pusher-js requires `@react-native-community/netinfo` internally. I added pusher-js in v1.6.0 without it.

  It is now a dependency of the app, at **11.3.1**, the version Expo SDK 51 pins. The lockfile is regenerated.

  **Why nothing caught this earlier.** pusher-js does not declare netinfo as a peer dependency — it simply requires it inside its React Native build — so `npm` never warned, and a sweep of our own imports never saw it either, because none of our code imports it. **Only bundling the app finds it**, which is why Gradle was the first thing to notice, four and a half minutes into a build.

## New

- **`npm run verify:bundle`** installs the app's dependencies and runs Metro exactly as Gradle's bundle step does. It takes about forty seconds and catches this entire class of failure — a missing or broken module — before a build is ever started. **This release was verified with it: 1,219 modules, a 3.26 MB bundle, no errors.**

- **The platform now checks the app source as well as the workflow.** v1.8.11 taught *Check GitHub setup* to notice a stale `.github/`; it now does the same for `mobile/`, which is the other half of the same problem:

  - *"mobile/ is revision 1.8.12 — current."*
  - *"mobile/ on main is revision 1.8.0; this platform ships 1.8.12. Push the mobile folder from the current release."*

  Pushing one half without the other was going to keep costing a build at a time.

## What to do

Push **both** `.github/` and `mobile/` to your build repository, then build.

`mobile/package-lock.json` is part of this — it is how the build installs exactly these versions, and it is what carries netinfo.
