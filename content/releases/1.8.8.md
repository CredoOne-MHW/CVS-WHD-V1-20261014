## AS-IS

Everything from v1.0.0 to v1.8.7 is unchanged. No screen, field or behaviour was removed.

## Fixes

- **A build with no signing key ran for ten minutes before saying so.** An Android app has to be signed, and there are two ways to do it: `MOBILE_SIGNING_SECRET` on the platform, or the four `ANDROID_*` secrets in the build repository. With neither, the build installed every dependency, branded itself, ran prebuild, and *then* failed at the signing step.

  The platform could have known. It can already read which secrets a repository holds — that is how *"Set up secrets in GitHub"* works — so it now checks before dispatching and refuses in about a second, naming which secrets are missing and both ways to fix it.

- **"Check GitHub setup" has a fifth answer: Signing.** It says which of the two routes is in use, or that neither is, before anybody presses Build.

- **The `MOBILE_SIGNING_SECRET` row no longer says "optional" without saying what it costs.** It now reads: one of these two is required for Android; with neither, an Android build fails at the signing step.

- **Not being able to check never blocks a build.** If GitHub cannot be reached, or the token cannot read secrets, the answer is "unverified" and the build goes ahead — the build itself still refuses to produce an unsigned app. Refusing a build because we could not check would be worse than letting it report the truth.

## Why the platform does not simply make this one up

`MOBILE_BUILD_SECRET` is now made and kept by the platform (v1.8.1), and the obvious question is why `MOBILE_SIGNING_SECRET` is not.

They are not the same kind of secret. The build secret signs messages in flight. **The signing secret is what encrypts every company's Android keystore at rest**, and its whole purpose is that the database on its own cannot sign anything. Generating it and storing it in that same database would keep the ceremony and throw away the point.

So it stays a platform setting. It is **one value, set once, for every company for ever** — and then the platform makes, keeps and uses a permanent key per company with nothing further to do.

## What to do

```
openssl rand -hex 32
```

Add it as **`MOBILE_SIGNING_SECRET`** in the platform's environment (Vercel → Settings → Environment Variables → Production), redeploy, and build again. Nothing else — no keystore, no `keytool`, no `ANDROID_*` secrets.

**Keep that value.** It is the only thing that can decrypt the signing keys. Lose it and no existing app can ever be updated again; every phone needs an uninstall and reinstall.
