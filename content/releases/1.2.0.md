## AS-IS

Versions 1.0.0 and 1.1.0 continue unchanged except where listed below. No module, screen, field, permission or fix from an earlier version has been removed or altered — Sales Order grouping, Convert to Invoice with Discount and Gross, the Outstanding / Upcoming split, Company Name on leads, the rebuilt WhatsApp Logs, Integration › Needs attention, the compact UI and the Client Journey scroll area all behave exactly as in 1.1.0.

## New Features

- **Delete a client.** Client › Clients now has a delete action next to View journey on each row, verified by a one-time code on WhatsApp — the same gate Leads already use.
  - **Step 1 — what goes with it.** Before any code is sent, the dialog lists the client's footprint: sales order lines, unpaid invoices with their amount, pay-ins received with their amount, and support tickets with the open count. A reason can be recorded.
  - **Step 2 — OTP.** A 6-digit code is sent to the signed-in user's WhatsApp number (the company's number if the user has none) through the existing **Delete OTP** webhook event. Valid 5 minutes, 5 attempts.
  - **Step 3 — delete.** The client leaves Clients, the Service Board, Subscription Management and the client's support page. Its sales orders, invoices, pay-ins and tickets go with it, so no orphan rows are left behind in Sales Order, Invoice or Pay-In.
- **Nothing is erased.** A full snapshot — profile, journey, sales orders, invoices, pay-ins and tickets — is archived in the company's own database before the live rows are removed, together with who deleted it, when, and the reason given. The activity log records the same. Payment attachments in S3 are left untouched, so a deleted client can be reconstructed in full.
- **Delete is a permission, and it is never inherited.** Client › **Clients** now offers **Delete** in Role Management. Unlike every other sub-module action, it does **not** follow the Client module: a role has it only when the box on the **Clients** row is ticked, so no role that exists today silently gains the power to delete a client. The grid says so on the row. The company owner keeps full access as before, and Super Admin › Company › Modules can still restrict or pause it per company.

## Updates / Modifications

- The **Delete OTP** webhook event now covers both leads and clients; its description reads "One-time code to confirm deleting a lead or a client." The event key, template and any webhook already configured for it are unchanged and need no edit.
- A client that is deleted is never silently re-created: promotion of converted leads skips deleted records, and its recurring dues stop being generated.
